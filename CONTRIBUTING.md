# Contributing to UniMarket Final

Each member must accept the collaborator invitation, use their own authorized GitHub authentication, and commit only the work they actually complete or have agreed to maintain. The repository owner remains Praneethvelagapudi.

On a shared workstation, signing into a browser may not change Git's authentication. Use Git Credential Manager or GitHub Desktop's secure sign-in flow, confirm the authenticated account before pushing, and never put passwords or access tokens in files or commit messages.

Set the local repository identity to the actual contributor's name and verified GitHub email or their GitHub-provided noreply email. The commit author and committer identify the credited author and the person recording a commit; the authenticated push identifies the account performing the upload. Agent-operated actions should be described as assistance on that account owner's behalf.

Use a module branch, add only the intended files, inspect the staged diff and run checks relevant to the change. Commit messages must explain the result. Existing code imports should be labelled as imports and use actual dates. Shared files must retain accurate credit; report responsibility is not evidence of exclusive authorship.

All four members' assigned module imports are published through their respective authenticated accounts. The complete application source is included. Deployment configuration, credentials, generated binaries and private evidence remain excluded.

After assembling or changing modules, run the complete Flutter suite, static analysis and the appropriate Android workflow checks. Recorded results from the earlier complete application are historical evidence and do not replace checking the newly assembled checkout.
